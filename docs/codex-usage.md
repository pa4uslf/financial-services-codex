# Codex Usage Notes

This fork adds Codex-facing navigation and maintenance guidance around a Claude
financial-services plugin repository. The underlying plugin runtime remains
Claude-oriented: Cowork plugins, Claude Code plugin manifests, and Claude
Managed Agent cookbooks.

## What Codex Can Safely Do Today

- Navigate the repository using `AGENTS.md`, `.agentlens/INDEX.md`, `CLAUDE.md`,
  and this file.
- Edit plugin manifests, markdown skills, agent prompts, cookbook YAML, and
  documentation.
- Run local validation with `python3 scripts/check.py`.
- Sync bundled agent skills from canonical vertical skills with
  `python3 scripts/sync-agent-skills.py`.
- Dry-run Managed Agent cookbook payloads with `bash scripts/test-cookbooks.sh`.
- Use the financial-services skills as source material when drafting analyses,
  provided the user understands that financial, legal, tax, accounting, and
  compliance outputs require qualified human review.

## What Is Not Codex-Native Yet

- There is no `.codex/skills` package generated by this repository.
- There is no Codex MCP registration script for the provider endpoints.
- There is no validated `codex` CLI install flow equivalent to the documented
  `claude plugin ...` commands.
- The Claude plugin marketplace manifest is not a Codex plugin manifest.

## Recommended Codex Workflow

For documentation or repository-structure work:

```bash
python3 scripts/check.py
```

For skill source edits:

```bash
python3 scripts/sync-agent-skills.py
python3 scripts/check.py
```

For Managed Agent cookbook edits:

```bash
python3 scripts/check.py
bash scripts/test-cookbooks.sh
```

## Adapting A Skill For Codex

When a task asks to reuse a Claude skill in Codex:

1. Start from the canonical source under
   `plugins/vertical-plugins/<vertical>/skills/<skill>/SKILL.md`.
2. Preserve domain disclaimers and human-review requirements.
3. Create a separate Codex adaptation artifact instead of changing the Claude
   source format in place.
4. Validate that the adapted artifact is actually loadable by the target Codex
   environment before documenting it as supported.

Good target shapes include:

- A documented manual workflow in `docs/`.
- A conversion script that emits a local Codex skill package.
- A small, explicitly named Codex package committed separately from the Claude
  plugin source.

## MCP Connector Caution

MCP manifests in this repository list third-party financial data providers.
They may require subscriptions, credentials, firm approvals, and compliance
review. Do not invent credentials or mark an MCP integration as working until it
has been configured and tested in the target environment.

## Commit Checklist

Before pushing Codex-facing changes:

1. Confirm the diff does not mutate unrelated financial workflow content.
2. Run the relevant validation commands above.
3. Keep local state such as `.omx/` out of the commit.
4. Mention whether the change is documentation-only or changes runtime behavior.
